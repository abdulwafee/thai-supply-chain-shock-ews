## Documented non-blocking limitations

**`citation_metadata_deferred`** — No CITATION.cff exists. It requires a verified personal author and none is available; the packaging metadata uses a collective attribution rather than a fabricated individual.

> Not blocking: A source-checkout release does not require citation metadata, and a citation file naming a person who has not approved it would be worse than none.

**`standalone_distribution_not_supported`** — Fifteen modules resolve repository resources through paths relative to the source tree, so the built wheel installs and imports but cannot reach configs, docs or mapping tables. The wheel and sdist are built for content inspection only.

> Not blocking: The owner chose a source-checkout release, which is exactly the mode that works and the mode CI and the clean-tree verification both use. The limitation is blocking for a PyPI release and that is why PyPI publication is neither supported nor authorised here.

**`python_311_not_supported`** — The supported floor is 3.12 and 3.12 is the only tested version. Python 3.11 is not supported: the resolved set requires 3.12 and above. Metadata permits 3.13 and later; nothing here has run on them.

> Not blocking: It is the owner's decision, applied consistently across metadata, both locks, CI and the setup instructions, and verified by reading all five.

**`data_backed_reproduction_requires_external_official_files`** — 109 registered data-backed tests re-audit official third-party downloads. They are skipped by name and with a reason when those inputs are absent, and never counted as passing.

> Not blocking: The files are obtainable from their publishers and the acquisition code, URLs and checksums all ship. Tier 2 of the reproducibility guide is the route.

**`unresolved_third_party_redistribution_terms`** — OIE, NESDC and EPPO state no terms of use; the archived World Bank Pink Sheet pages state none inline. All four remain unresolved and no raw byte from any of them is in the release.

> Not blocking: The conservative route is already taken: the bytes are excluded and only the acquisition code, URLs and checksums are published. Public download access is not a redistribution right, and the release does not behave as though it were.

**`lock_is_platform_scoped`** — Both locks were regenerated and verified on CPython 3.12 / Windows AMD64. They pin versions, not platform wheels, and have not been installed here on Linux.

> Not blocking: Every pinned version publishes cross-platform wheels and CI installs from these exact files, so the first CI run verifies the other platform rather than a claim made here.

**`dependency_audit_coverage_is_incomplete`** — 26 of 27 pinned distributions were covered by the vulnerability audit. ['packaging'] were not: pip-audit omits packages that are also dependencies of its own environment.

> Not blocking: No advisory was found for anything it did check, and nothing was hidden -- the uncovered pins are named. Reporting the package count without the gap would be the failure; a clean audit of most of a set is not a clean audit of the set.

## What this document does not claim

- It does not say the built wheel is a usable runtime. Fifteen modules resolve repository resources beside the source tree, so an isolated installed distribution cannot reach the project's configuration, documentation or mapping tables.
- It does not license anyone else's data. The MIT grant covers this project's own code and documentation; World Bank, NESDC, OIE and EPPO material is theirs, unresolved where it is unresolved, and no raw byte of it is in this release.
- It does not say the release is secure. Two scanners found nothing today, against one advisory database.
- It does not reopen any modeling result. The development programme closed at E1 without a supported incremental commodity model, D3's persistence forecasts remain the registered operational reference, the evaluation was latest-vintage rather than a real-time backtest, and the locked final test is still sealed and unopened.
